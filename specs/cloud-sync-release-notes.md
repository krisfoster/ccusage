# Release notes — cloud sync and dashboard

Copy for the release that first ships `ccusage sync` and `ccusage compare`. The repository's
release notes are generated by tagpr from PR titles, so this is the hand-written section to paste
above them.

## Highlights

**Cloud sync — one bucket, every machine.** `ccusage sync setup` signs you in with `gcloud`, picks
a project and creates a private Google Cloud Storage bucket; `ccusage sync run` folds each agent's
local logs into per-day shards and uploads only what changed. A second machine points at the same
bucket and adopts its identity, so laptop and desktop merge into one set of totals rather than two.
Machines that saw the same session are counted once, and a partial overlap is reported rather than
silently suppressed.

**Dashboard.** `ccusage sync dashboard` serves the bucket as a single page on `127.0.0.1`;
`--deploy` publishes the page (and only the page) to a separate public bucket, and `--share` mints
a time-limited link that lets someone read the numbers without a Google account. Spend over time,
plus breakdowns by model, agent and machine.

**Provider comparison.** `ccusage compare` reprices the same tokens at other providers' published
list rates, with a source link on every price and sortable columns, so "what would this month have
cost elsewhere" is one command.

## Notes

- Nothing is uploaded until you run `ccusage sync setup`. Local reports are unchanged.
- Project paths are hashed with a per-bucket salt before upload; `sync.redactProjects: false` opts
  out.
- Data buckets are created with public access prevention enforced, and setup and `doctor` refuse a
  bucket that is world-readable.
- Read access to the data bucket is all-or-nothing, and object names alone reveal your machines,
  the agents you use and which days you worked — share a signed link rather than granting
  `objectViewer`.
- Maintenance commands: `ccusage sync status`, `doctor`, `repair`, `prune`, `forget` and
  `merge-machine`. An interrupted run is safe to re-run; `repair` rebuilds derived views.
